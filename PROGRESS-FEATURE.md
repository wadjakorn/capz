Unit tests + e2e pin English. Verified: 489 unit tests, `tsc`, `pnpm build`, web e2e 43 passed + mobile 9 passed (local headless shell), Rust i18n tests; clippy clean on touched files (remaining Linux-only dead-code errors pre-exist). Interactive Mac check (tray relabel, onboarding on a fresh install) pending.
- [x] **More backdrop styles** — 18 procedural presets on top of the 7 linear gradients: Minimal (Paper, Ink, Fog, Sand, Hairline, Dot Grid) and Art (Risograph, Gingham, Houndstooth, Tartan, Breton, Bauhaus, Memphis, Aura, Klein, Terrazzo, Op Art, Xerox Zine). Picker is one Gradient / Minimal / Art / Solid row over a 6-column grid, so the largest family still fits in two rows. No schema change (`presetId` was already a free string). Verified: unit tests, `tsc`, `pnpm build`, web e2e (41 passed, run against a local headless shell); interactive Mac check pending.
- [x] **OCR text reader** — native on-device OCR (macOS Vision + Windows.Media.Ocr) behind an `OcrBackend` trait; toolbar "Detect text" toggle; transparent selectable overlay (`data-ocr-layer`) → native selection + right-click/⌘C copy; Latin+Thai with graceful degradation (one-time notice when native Thai unavailable); idempotent per-image result cache (re-toggle doesn't re-detect); detection cleared on every new image. Windows build + interactive macOS smoke (detect→select→copy, export-has-no-text-artifacts) pending verification.
- [x] **Settings revamp (CP-0053)** — Settings is five intent-named pages (Capture / Editor / After capture / Library / App) behind a labelled sidebar with search, each page showing its everyday rows and folding the tuning into `Advanced (n)`. New surface: `registry.ts` (one table describing every setting: page, label, group, keywords, platform, `addedIn`), `lib/settingsNav.ts` (`openSettings(id)` — a store, so a deep link fired before the view mounts is no longer dropped, which the old `settings:focus-tab` emit did), `SettingRow` (label from the registry + `data-setting-id` + scroll/focus/flash), `AdvancedSection`, `VersionFooter` (running version + live update status, click → Updates), `SettingSuggestion` (one-off nudge, dismissal remembered; no trigger wired yet) and New badges driven by `addedIn` vs `general.lastSeenSettingsVersion`. Deep links from the editor toast, toolbar and history notice now call `openSettings`; `settings:focus-tab` and the `SettingsFocus` prop are gone. Two additive `general` fields, no schema bump. A drift test renders every page on both platforms and asserts the rendered ids equal the registry. Verified: 441 unit tests, `tsc`; **web e2e and the Mac build still to run** (no Playwright browser for Ubuntu 26.04 on the dev box; `pnpm build` needs network for Google Fonts).
- [x] **Smoother workspace switching + capture into an empty workspace** — a switch no longer moves `activeId` until the target's bitmap has decoded (`pendingId` → `commitSwitch`, `src/stores/workspaces.ts`; preload in `useWorkspaceSession`, `src/lib/imagePreload.ts`), and EditorStage takes the preloaded element synchronously, so the image and its annotations land in one render — no blank frame, no annotations over the wrong image. `WorkspaceSwapOverlay` hides the canvas until `onStageViewSettled` (after fit/centre/scroll restore) and covers the gap: the target's tile thumbnail lifts out of the bar into the canvas, shimmers if the decode is slow, then focus-pulls into the real canvas; captures/close/reopen get a short "develop" fade; `prefers-reduced-motion` → crossfade. With `workspaces.onCapture: "new"`, a capture into an **empty** active workspace (no image) now fills it instead of appending/evicting; `adoptCapture` returns an outcome so toasts are accurate. Verified: unit tests, `tsc`, `pnpm build`; interactive Mac check pending.
- [ ] **Copy/paste annotation elements** — duplicate any overlay element (arrow, text, sticker, blur rect, pin) via `⌘C` / `⌘V` on the editor stage. Preserve type + style; offset paste position so it's visible.
- [ ] **Auto-shrink large captures** — cap exported image at a configurable max dimension (default e.g. 2560px long edge) to keep file sizes sane on 5K/6K displays. Setting lives in Output tab; "Original" option to disable.
- [ ] **Layout-independent global shortcuts** — bind hotkeys by physical key (USB HID / ANSI/ISO position) rather than the typed character, so `⌘⇧P` still fires when the active input source is Thai (where the same physical key produces `ญ`), Russian, Dvorak, etc. `tauri-plugin-global-shortcut` resolves accelerators by Unicode char on most paths, so a US-layout binding silently breaks when the user switches IME. Investigate: macOS `kVK_*` keycodes via `CGEventSourceKeyboardType` / `UCKeyTranslate` round-trip, Windows `MapVirtualKey(MAPVK_VSC_TO_VK)` with scancodes. Likely needs a custom shortcut layer below the plugin, or upstream patch. Settings UI should display the layout-localized label for the bound physical key.

## Landed

- **History preview overlay** (landed 2026-10-05) — selecting a History item shows it large over the canvas (`src/components/editor/HistoryPreview.tsx`); deselecting, Esc, ✕ or clicking the dim closes it, and switching sidebar tab hides it without dropping the selection. The bar repeats the item's sidebar actions (Reveal / Copy / Trash, now one shared `useHistoryActions` hook) plus **Add to current workspace** (same path as dropping a row; double-click the picture does the same). Smoothness: the in-memory 128px thumb paints blurred on the click frame, then a canvas-sized JPEG from the new `read_image_preview` command (raw bytes via `ipc::Response`, not base64) is decoded off-screen and faded in; a 6-entry LRU of blob URLs (`src/lib/historyPreview.ts`) plus a 120 ms hover prefetch make most clicks hit cache. Only opacity/transform animate; no backdrop blur. Verified: unit tests, `tsc`, `pnpm build` + `cargo clippy -D warnings` on the Mac; interactive Mac check pending.

- **Keep tool active (per tool)** (landed 2026-09-23) — user report: had to re-pick Shapes after every rect. `general.keepToolActive` is a **per-tool map** (`src/lib/config.ts`, `KeepToolActive`), every sticky-capable tool defaulting to on; `isStickyTool` (`src/stores/editor.ts`) is the single rule, used by the empty-canvas click path (`EditorStage.tsx`) and the Esc ladder. A sticky tool stays selected: clicking empty canvas deselects and starts the next element in the same click. Three controls, all acting on the **active** tool: editor sidebar row "Keep <tool> active (K)" — in the tool-options panel while a tool has options, in GlobalToolsPanel otherwise (the two are mutually exclusive); works on web, where the flag lives in memory only, the `K` shortcut with a toast, and per-tool rows in Settings → General (desktop). Select/crop can never be sticky. Verified: unit tests, `tsc`, `pnpm build`; interactive Mac check pending.

- **Anonymous active-install count + feedback inbox** (landed 2026-09-12) — new `worker/` (Cloudflare Worker + D1, deployed at `capz-api.banana3339.workers.dev`). The updater now fetches `latest.json` through the Worker (gh-pages stays as the fallback endpoint) so update checks can be counted; version/target/arch ride on the URL template. **Opt-in** `updates.shareInstallId` (default off, SignPath privacy terms) adds a random UUID header stored only as a salted hash → `GET /stats` gives DAU/WAU/MAU + version/platform breakdown. Toggle lives on the onboarding Done screen and Settings → Updates; installs that have not opted in get a toast once per new app version. UUID lives in its own `telemetry.json` (`src/lib/installId.ts`), deleted on opt-out, re-minted on opt-in. Settings → **Feedback** tab posts anonymous bug/feature reports (`src/lib/feedback.ts`, no install id by design) → D1 → issue in private `capz-inbox`; per-IP + daily caps + kill switch. README privacy policy rewritten to match. Added `tauri-plugin-opener` for the "Open GitHub Issues" fallback. Verified: worker + app unit tests, `tsc`, live smoke against the deployed Worker.

- **Marketing landing page (`/`)** (landed 2026-07-21) — merged the standalone `capz-site` (a separate Cloudflare Worker, TanStack Start) into this repo as the home route so capz-web.pages.dev serves both the landing and the `/paste` editor from one static export. Ported Nav/Hero/Features/Install/Footer + th/en i18n into `src/components/site/` and `src/i18n/`, dropping `motion` and `@tanstack/react-query` (replaced with tw-animate-css entrances and a plain `useEffect` GitHub-release fetch — **zero new deps**) and `localStorage` (CLAUDE.md rule; language is in-memory, default `th`). `.site-landing` wrapper in globals.css forces the dark graphite palette regardless of ThemeManager. Nav + Hero link out to `/paste`. Removed the old `public/_redirects` `/ → /paste/` rule so the landing is reachable. `page.tsx` stays a server component exporting metadata. Verified: `tsc --noEmit` clean, `next build` static export (11 pages) OK. The original `capz-site` Worker is left as-is.
- **Browser paste editor (`/paste`)** (landed 2026-07-03) — browser-only companion: paste OS screenshot (Win+Shift+S / ⌘⌃⇧4), drag-drop, or file-pick; annotate with existing editor tools; Ctrl/Cmd+C copies result to clipboard; download button saves file. Deployed to Cloudflare Pages via Cloudflare's Git integration (build `pnpm build` → `out/`; `main` → production, branches/PRs → preview URLs). Platform split via `isTauriRuntime()` ([src/lib/platform.ts](src/lib/platform.ts)); desktop-only toolbar items (capture split, OCR toggle, clear workspace, settings) hidden on web. Settings store runs in-memory `DEFAULT_CONFIG` on web. Safari clipboard path constructs `ClipboardItem` synchronously around the pending blob promise to preserve user activation. Web export primitives in [src/lib/webExport.ts](src/lib/webExport.ts). Verified: unit tests (`pnpm test:unit`), Playwright e2e ([e2e/web/paste.spec.ts](e2e/web/paste.spec.ts)).
